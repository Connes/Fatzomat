# together V1.3 – technische Änderungen

## Umgesetzte Arbeiten

- **AI-Quota serverseitig fixiert:** `consume_ai_generation_quota()` akzeptiert keine vom Client steuerbaren Limits mehr. Die Grenzen 5/Stunde und 20/24h liegen ausschließlich in der Datenbankfunktion.
- **RPC-Berechtigungen gehärtet:** Die User-Triggerfunktion `handle_new_user()` ist nicht mehr über die `authenticated`-API-Rolle ausführbar.
- **AI-Event-Tabelle clientseitig abgeschottet:** RLS-Deny-Policy und fehlende Tabellenrechte verhindern direkten Zugriff auf `ai_generation_events`.
- **Edge Function V8 deployed:** `generate-recipes` verwendet die neue parameterlose Quota-RPC und ausschließlich die strukturierte Taxonomie für Fleisch/Fisch-Prüfungen.
- **FoodPolicy bereinigt:** Keine Klassifizierung mehr anhand von Kategorie- oder Anzeigenamen. Vegetarisch/Vegan/Fisch/Fleisch basiert auf `dietary_type` und `protein_type`.
- **FoodRepository typisiert:** Die verbleibenden Legacy-Map-Methoden wurden entfernt. Food-Zugriffe laufen über `Food`-Modelle.
- **Offline-UI korrigiert:** Der Offline-Hinweis verspricht keine nicht vorhandene Mutation-Queue mehr. Der Cache bleibt ein Read-Fallback und keine Autorisierungsquelle.
- **Release-Artefakt bereinigt:** `.env.local` wurde aus dem Projektartefakt entfernt. `.env.example` bleibt als Vorlage.
- **CI bereinigt:** Leere doppelte `ci.yml` entfernt.
- **Release-Verifikation verschärft:** `pubspec.lock`, Plattformstruktur und saubere lokale Konfiguration werden vor der Verifikation geprüft; Dependencies werden mit `--enforce-lockfile` geladen.
- **Bootstrap deterministischer:** `setup.sh` erzeugt keine Android-/iOS-Struktur mehr automatisch. Plattformdateien müssen Bestandteil des vollständigen Repositorys sein.
- **Historische Root-Dokumentation aufgeräumt:** Versions-/Release-Dokumente liegen unter `docs/archive/`.

## Bewusste Restpunkte

### pubspec.lock
Die Lockdatei muss mit Flutter/Dart in einer lokalen Flutter-Umgebung erzeugt und versioniert werden. In dieser Build-Umgebung ist das Flutter SDK nicht installiert; eine künstlich erzeugte Lockdatei wäre nicht reproduzierbar und damit schlechter als eine ehrliche Fehlermeldung.

Ausführen:

```bash
flutter pub get
```

Danach muss `pubspec.lock` im Repository verbleiben. `scripts/verify_release.sh` erzwingt anschließend `flutter pub get --enforce-lockfile`.

### Android/iOS-Plattformstruktur
V1.3 erzeugt Plattformdateien nicht mehr heimlich. Das vollständige Repository muss `android/` und `ios/` enthalten. Fehlen sie, bricht Bootstrap/Release-Verifikation bewusst ab.

### Leaked Password Protection
Die Supabase-Auth-Einstellung ist eine Dashboard/Auth-Konfiguration und keine sichere Änderung per SQL-Migration. Sie muss im Supabase Auth-Bereich aktiviert werden, bevor Passwort-Authentifizierung produktiv verwendet wird. Anonymous Auth bleibt davon getrennt.

## Sicherheitsprinzip

Client-Rollen erhalten nur die explizit benötigten API-Rechte. Sicherheitskritische Geschäftsregeln wie AI-Quota-Limits werden serverseitig festgelegt und nicht aus Request-Parametern übernommen.
