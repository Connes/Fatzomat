# V78 – Entscheidungsanfrage visuell vereinheitlicht

## Ziel
Die Auswahl bei einer eingehenden Entscheidungsanfrage verwendet dieselben freigegebenen Karten wie die Startseite. Dadurch bleibt die Bedienlogik zwischen Startseite und Partner-Entscheidung konsistent.

## Änderungen
- Vier freigegebene Together-Karten werden in der Entscheidungsanfrage als 2x2-Auswahl verwendet.
- Alle vier Karten behalten eigene semantische Labels und sind als Buttons zugänglich.
- Die Karten werden mit `BoxFit.contain` dargestellt, damit das Seitenverhältnis der freigegebenen PNGs erhalten bleibt.
- `CollaborationRepository` wird auf der Entscheidungsseite lazy erzeugt. Ein reines Rendern der Seite benötigt damit keine initialisierte Supabase-Instanz.
- Die bestehende Entscheidungslogik bleibt unverändert: Annahme zuerst, danach Auflösung mit `decision_request_id`.
- Version auf `0.1.0+78` erhöht.
- Neuer Widget-Test prüft die vier zugänglichen Auswahlmöglichkeiten der Entscheidungsanfrage.

## Absichtlich nicht geändert
- Keine neuen Datenbanktabellen oder RPCs.
- Keine Änderung am Entscheidungsstatusmodell.
- Keine Änderung an den bereits freigegebenen Startseiten-Assets.
