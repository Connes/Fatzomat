# V1.0 Technical Audit

## Implemented release blockers

- AI generation is rate-limited server-side to 5 requests/hour and 20 requests/24h per authenticated user.
- Quota consumption is serialized per user with a PostgreSQL transaction lock.
- AI input size is bounded and food IDs are validated before database/OpenAI work.
- `generate-recipes` is deployed with Supabase JWT verification enabled.
- All current `public` SECURITY DEFINER functions have `search_path = public` and are not executable by `anon`.
- Foreign-key indexes reported by the Supabase performance advisor were added.
- Supabase migrations are applied to project `oidxezjdwqktpxuypbfb`.
- Hard-coded Supabase client configuration was removed from Dart source and moved to `.env.local`/`--dart-define`.
- Historical nested project copy `v84fix/` was removed.
- CI quality gate and local release verification were added.

## Verified remotely

- `ai_generation_events` exists.
- `consume_ai_generation_quota(integer, integer)` exists.
- 0 public SECURITY DEFINER functions lack `search_path = public`.
- 0 public SECURITY DEFINER functions are executable by `anon`.
- Supabase performance advisor reports no remaining unindexed foreign keys.

## Remaining advisor findings that are intentional or need separate work

1. `ai_generation_events` has RLS without client policies. This is intentional because the table is accessed through the security-definer quota RPC, not directly by clients.
2. Supabase reports authenticated execution of several SECURITY DEFINER RPCs. These are application RPC endpoints and must remain callable by the authenticated app; each must continue to enforce `auth.uid()`/membership checks internally.
3. Anonymous-sign-in policy warnings are expected because the app intentionally uses Supabase anonymous authentication. This is a product/authentication-model decision, not a hidden anonymous data bypass.
4. Multiple permissive `recipes` policies remain. They are a performance cleanup task, not a release-blocking authorization defect.
5. Unused-index notices are retained for now. The database is new and usage statistics are not yet representative; removing indexes based on early usage would be premature.

## Local verification limitation

The build environment used to prepare this archive does not contain the Flutter/Dart CLI, so `flutter analyze`, `flutter test`, and `flutter build` could not be executed here. The source changes were syntax-checked where possible, and the remote Supabase migration/deployment was executed and verified.
